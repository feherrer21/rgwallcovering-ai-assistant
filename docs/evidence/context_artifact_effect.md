# Context Artifact — Before / After

**Task:** T0.4 (`05_tasks.md`)
**Method:** `00_context_experiment_method.md`
**Artifacts:** `retrieval_before.py`, `retrieval_after.py`, `CLAUDE.md`

Both modules were generated by subagents with **cold context windows** — no
access to the working session, the specification, or any repository file. The
only difference between the two runs is that the second was permitted to read
`CLAUDE.md` first. Same task prompt, verbatim, in both.

The method note originally recorded a weaker design (cold vs warm) as a
time-saving compromise. It was then executed properly, because the cleaner
version cost about three minutes. The note has been corrected.

## What the artifact caused

**1. The trust-tier mechanism exists at all.** This is the finding that
matters. `grep tier retrieval_before.py` returns nothing. Without tiers, a
retrieved passage arrives at the prompt with no indication of whether it is
the client's own words, a third-party directory listing, or general trade
knowledge — and success criterion S2 becomes unenforceable, because there is
no way to distinguish "may assert about the business" from "may explain in
general". The cold version is not defective code; it is code that could not
know this project's central constraint.

**2. Defensive complexity born of uncertainty disappeared.** The cold version
carries three tuples of candidate field names — `("text", "content", "chunk",
"chunk_text", "page_content", "body")` and two more — plus a `_first_present`
helper and a `_parse_chunk_record` function to try them in order. All of it
exists because the ingestion format was unknowable from the task description.
`CLAUDE.md` states the schema, and the entire apparatus vanishes in favour of
direct key access that raises on a missing field. Roughly 60 lines of
machinery replaced by an assumption that is now documented and therefore
safe.

**3. Scale matched the problem.** Gone: a threading lock around model loading,
a second lock around index caching, a per-source diversity cap, an argparse
CLI, a character-budget context formatter, and three of four exception
classes. For a corpus of ~300 chunks queried by one small website, none of it
was load-bearing. `CLAUDE.md` says so explicitly, and the model complied.

**4. Conventions were followed without being asked in the prompt.** Comments
and docstrings in Spanish, user-facing strings in English, dataclasses across
module boundaries, `pathlib`.

**5. Deferral is framed correctly.** Both versions return an empty list below
threshold. Only the second treats that as a success state — logging at debug
rather than warning, and offering no fallback that softens an empty result
into a partial answer.

## What the artifact did *not* cause

**The relevance floor.** Both versions have one. The cold model produced
`DEFAULT_SCORE_THRESHOLD = 0.30` and an empty-return path unprompted.

This weakens a claim in `03_spec.md`, which presents the floor as the central
design insight. It is not an insight; it is what a competent model does by
default. What `CLAUDE.md` changed is the *reason* attached to it: the cold
version documents the threshold as "a floor against obvious noise rather than
a precision knob", which is exactly wrong for this corpus. Here the floor is
not noise filtering — it is the mechanism that stops a corpus of decorative
essays from producing confident, fluent, fabricated answers. Same code,
different purpose, and the purpose is what determines how it gets tuned in
phase 6.

Recorded because the alternative — quietly claiming the artifact produced the
floor — would have been the flattering version of this comparison.

## What got worse

Two things in the cold version were worth keeping and the artifact's sizing
guidance removed them:

- **`max_per_source`**, a cap on how many chunks one page may contribute.
  With 28 blog posts of uneven length, a single long essay can plausibly
  dominate the retrieved context. This is a real diversity control and its
  loss is a regression. It will be reinstated in the production module.
- **`warm_up()`**, which loads the model and index ahead of the first query.
  Without it the first visitor pays the model-load latency. Also worth
  reinstating.

Both are casualties of "build for the size this actually is" being applied
without judgement. The instruction is right; it was followed slightly too
literally. `CLAUDE.md` will not be amended for this — an artifact that
enumerates every worthwhile exception stops being read.

## Limitations of this comparison

- **n = 1 per condition.** No repeats, so run-to-run variance is unmeasured.
  Some portion of the 64% size reduction is plausibly noise rather than
  signal; the tier count is not, since it is a categorical presence/absence.
- Both runs used the same model at the same effort. Nothing here generalises
  to other models.
- The subagent self-reported 182 lines; measurement gave 232. Self-reported
  metrics from a model were not trusted anywhere in this table.

## Incidental finding, carried to phase 1

The second subagent flagged a genuine integration risk unprompted: it used
fastembed's `query_embed()`, which applies the BGE query-instruction prefix,
and noted this is correct only if ingestion embeds passages with plain
`embed()`. Getting this asymmetry wrong would silently degrade every
similarity score in the system. Recorded as a constraint on T1.6.

## Conclusion

The artifact did not make the model a better programmer. The cold output is
competent, and deliberately was not compared against a strawman. What the
artifact supplied was **project-specific correctness** — the constraint that
makes the product safe (tiers), the facts that remove guesswork (schema), and
the sense of scale that stops a 300-chunk problem being solved with
infrastructure for 300,000.
